### 1. Session tokens generated with `Math.random()`

**Location:** [`src/auth/session.ts:142`](../src/auth/session.ts#L142)

```diff
- const token = Math.random().toString(36).slice(2) + Date.now().toString(36);
+ import { randomBytes } from "node:crypto";
+ const token = randomBytes(32).toString("base64url");
```

**Why it matters.** `Math.random()` is not cryptographically secure; tokens are predictable after observing ~600 samples (V8 xorshift128+ state recovery).

**Suggested test**

```ts
test("session tokens are 256-bit and unique", () => {
  const seen = new Set<string>();
  for (let i = 0; i < 10_000; i++) seen.add(newSessionToken());
  expect(seen.size).toBe(10_000);
});
```

</finding>

### 2. Path traversal in upload handler

User-controlled `filename` flows into `path.join(UPLOAD_DIR, filename)` without normalization:

> Taint flow:
> 1. `req.body.filename` (`src/api/upload.ts:41`)
> 2. `sanitizeName()` only strips `\0` (`src/util/fs.ts:12`)
>    > Nested note: the helper was added in PR #1182 and never tested on `..%2f`.
> 3. `fs.writeFile(path.join(UPLOAD_DIR, filename))` (`src/api/upload.ts:57`)

Fix: resolve and verify the prefix:

```ts
const target = path.resolve(UPLOAD_DIR, filename);
if (!target.startsWith(path.resolve(UPLOAD_DIR) + path.sep)) throw new BadRequest();
```

</finding>
